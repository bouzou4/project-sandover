## Answer (≤5 lines)
AMD FidelityFX FSR 3.1 (upscaler 3.1.4 from SDK 1.1.4) runs on the GL 4.3 context as ten compute
programs built from the SDK's GPU headers, unmodified, plus a thin OpenGL backend. Temporal AA is
the only Sandover render path (design decision): native TAA at render scale 100 % (the default), the
upscaler below it. SMAA and FSR 1 are removed; VANILLA RENDERING is upstream's MSAA path. Pan
shimmer at 4K (run): raw 1 spp 1.45, MSAA 2x + SMAA 1.13, FSR 0.85; beach orbit: raw 2.61, FSR 1.19.

## Decisions
- Source: FidelityFX SDK 1.1.4 (the last release with the FSR 3.1 source), GPU headers only, in
  `third-party/fidelityfx/gpu` with the MIT licence beside them. The SDK's GLSL callbacks are
  Vulkan GLSL (separate `texture2D` and `sampler`, descriptor sets), so the backend carries an OpenGL
  variant: `shaders/fsr3/ffx_fsr3upscaler_callbacks_gl.h` (the same file with combined samplers, no
  sets, and the SPD atomic counter in a storage buffer), and one entry point per pass
  (`shaders/fsr3/fsr3_<pass>.comp`, the Vulkan pass files minus their binding numbers).
- Bindings: the target driver has 8 compute image units, and the Vulkan numbering (one space for
  textures, images and buffers) reaches 12. Each pass file lists its binding names in a
  `fsr3-bindings` line; `Fsr3Upscaler.cpp` numbers them per kind (texture units, image units,
  uniform blocks, storage buffers), prepends the `#define`s and binds the same list at dispatch. The
  luma pyramid needs 9 images in the SDK; with the atomic counter as a storage buffer it needs 8.
- Includes: expanded on the CPU like the C preprocessor does (no include-once: the SDK re-includes
  `ffx_fsr1.h` with other defines); `#extension` lines are dropped (`FFX_HALF 0`, no wave ops via
  `FFX_SPD_NO_WAVE_OPERATIONS`), so the programs need only GL 4.3 core.
- Version rule: these passes alone are `#version 430 core` compute (ADR-0013 amendment); when the
  context is below 4.3 or a program fails to build the engine reports `pc-temporal-aa-state` 0 and
  the game runs vanilla rendering (one log line). The context asks for 4.3 on Windows and Linux, 4.1 on macOS
  (`pipelines/opengl.cpp`).
- Jitter: Halton (2, 3) minus 0.5 over the SDK's phase count (8 x (display / render width)^2:
  8 native, 13 at 77 %, 18 at 67 %, 32 at 50 %). Applied once for every path: the vertex stage that
  feeds the rasterizer of each scene program (an allowlist by shader name in `Shader.cpp`) is
  wrapped, its `main()` renamed and a new `main()` adding `sandover_jitter * gl_Position.w` after it;
  `scene_jitter::set` loads the uniform into every listed program (`glProgramUniform2f`) when it
  changes. Buckets carry their own matrices from DMA (background `pc_camera`, merc
  `perspective_matrix`, generic and sprite hvdf, ocean and direct GS coordinates), and the clip-space
  offset covers all of them without touching any. The jitter is cleared before the text buckets and
  on frames without FSR, where the uniform is 0. The add is a select on a non-zero jitter
  (`mix(vec2(0), j * w, notEqual(j, vec2(0)))`), so a zero jitter adds exactly 0 even where `w` is
  not finite (a product would give `0 x inf = NaN`): with vanilla rendering the wrapped programs
  produce the same output as unwrapped ones, no shader-level difference.
- Jitter and velocity ("where jitter goes", left open by the motion-vector note): nowhere in the
  velocity. The wrapper adds the offset after `main()`, so merc's `mv_project` and the camera pass see
  unjittered positions, and FSR runs without `JITTERED_MOTION_VECTORS`. The camera pass reconstructs
  from the pixel centre with the unjittered matrices: the depth it reads was rasterized jittered,
  but re-projecting it through the unjittered matrices cancels the jitter to first order, so the
  vector is the unjittered `p_prev - p_cur`, which is what the SDK expects without
  `JITTERED_MOTION_VECTORS`. No jitter cancellation is needed.
- Placement (frame order): scene buckets at render size, single-sample; copy of the scene before the
  sprite bucket; sprite bucket; autogen reactive mask (scene against the copy); tile lights, bloom,
  sky flare; velocity pass; FSR 3; debug, HUD text and
  subtitle buckets at display size into the FSR output target; final pass (tonemap, HDR encode)
  unchanged. The scene renders at 1 sample (`Gfx::aa_samples`).
- Colour: the display-encoded scene buffer, FP16 headroom above 1;
  the HDR variant (`HDR_COLOR_INPUT`) when the FP16 target is on, the SDR variant otherwise. Exposure
  1 (a 1x1 texture of 0, which the callbacks read as 1); pre-exposure 1.
- HUD: the 2D HUD and HUD sprites draw in the sprite bucket with the scene, so they go through FSR,
  jittered like the scene and marked reactive by the autogen mask (the difference before and after
  the sprite bucket), so FSR takes them from the current frame rather than from a history the camera
  motion moves. Text (debug, HUD text, subtitle buckets) draws after FSR at display size, sharp at
  every scale. Below 100 % the sprite HUD is reconstructed from the render size until the HUD split.
- Settings (design decisions, 2026-10-18 and 2026-10-19): temporal AA is the only render path for
  the enhancements. Rows: VANILLA RENDERING (off by default: upstream's path, MSAA at the stock
  setting, no Sandover effects; it greys every other row and is the parity path), UPSCALER =
  TEMPORAL AA (FSR 3.1) (file `upscaler fsr3`; the second value is reserved for DLSS, which hides
  itself where unavailable), RENDER SCALE 100, 77, 67, 59, 50, 33 %, each with FSR 3.1's quality
  name and the render size at the current display size (`67% (QUALITY, 2560X1440)`; 77 % has no
  preset name). Default: temporal AA at 100 % (native). Bilinear, FSR 1 and SMAA are deleted
  (losing arms). The stock MSAA setting applies to vanilla rendering, stereo and XR only.
  `sandover-temporal-aa?` (not vanilla and `pc-temporal-aa-state` 1, i.e. not stereo or XR) is the
  check for rows that need accumulation; `sandover-temporal-upscaler?` is the same for menu rows.
  Older files: `antialias` and `smaa?` are skipped, `upscaler bilinear|fsr` keeps the default. No
  look knobs; sharpness stays at 0.8, the SDK sample's default. Engine: `pc-set-aa` 0 mode (0 MSAA,
  1 FSR 3.1), 1 render scale, 2 debug view, 3 sharpness, 4 jitter (2, 3 negate an axis: the sign
  check), 5 reset 2-4.
- Debug view: the SDK's debug pass (`pc-set-aa 2 1`, or the renderer debug window, `FSR 3`).
- Not for stereo or XR yet: they keep MSAA with the effects on until the temporal pass runs per eye.

## Input mapping
| FSR 3.1 input | Renderer source | Notes |
|---|---|---|
| colour (jittered) | scene colour texture at the sprite bucket's end (render size, 1 sample) | display-encoded, FP16 headroom with the HDR variant |
| depth | scene depth-stencil texture, same moment | GEQUAL cleared to 0: `INVERTED_DEPTH`; view depth `= (k0/2) / (d - (1+k1)/2)` from the frame camera's clip matrix (`MotionVectors` `w_k0`, `w_k1`) |
| motion vectors | `MotionVectors` RG16F velocity, render size | `p_prev - p_cur` in texel-grid pixels, +y up: FSR's sign and axes in GL texel space, scale `1 / render size`, no jitter cancellation |
| reactive mask | SDK autogen pass: scene before against after the sprite bucket | tonemapped, per-channel max, threshold 0.2, value 0.9 (SDK sample settings) |
| transparency and composition | none (a 1x1 zero) | |
| exposure | 1 | |
| camera near / far / FOV | from the clip matrix: depth factors above, tan of the half FOV from the clip rows | view to metres 1/4096 (game units) |
| jitter | Halton (2, 3), SDK phase count | content offset in texel-grid pixels; clip offset `2 j / size` (no y flip in GL) |
| frame delta time | render thread frame interval | clamped to 1 s |
| reset | `!MotionVectors::frame_valid()` | cuts, load blackout, resize, first frame, missing camera |

## Evidence
- Offline compile on the target driver (GL 4.3 core, 8 compute image units, 48 combined): all ten
  programs compile and link with the per-kind numbering; first build 2.8 s for the set
  (shading change pyramid 1.7 s, luma pyramid 0.56 s, the rest 37-123 ms), lazily on the first FSR
  frame.

## Open items
- The HUD split (sprite HUD after the upscale) is a design decision; until then the sprite HUD is
  reconstructed with the scene.
- Transparent water and other alpha-blended surfaces outside the sprite bucket are not in the
  reactive mask; FSR's shading change and luma instability passes handle animated texture there.
