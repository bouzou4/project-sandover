## Answer (<=5 lines)
RenderDoc is the primary tool: MIT-licensed, actively maintained, full GL 3.2-4.6 core capture support, scriptable Python API, per-draw GPU timings. Nsight Graphics still ships an "OpenGL Frame Debugger" in the current release but GPU Trace/Frame Profiler (the counter/timing engine) never supported OpenGL, and NVIDIA is now deprecating even the legacy GL debugger's shader profiler. Use RenderDoc as primary for capture/inspect/shader-edit; use in-engine `glQueryCounter(GL_TIMESTAMP)` + the existing Dear ImGui profiler as the main per-pass budgeting mechanism, since neither tool gives a first-class GL profiler. Nsight Graphics is a fallback only for basic GL draw-call/state inspection, not for AO-pass budgeting.

## Evidence
- RenderDoc repo license MIT, last push 2026-09-22, 11,113 stars, 51 open issues: `gh api repos/baldurk/renderdoc --jq '.license.spdx_id, .pushed_at, .stargazers_count, .open_issues_count'`
- RenderDoc latest tag `v1.46`, published 2026-08-31: `gh api repos/baldurk/renderdoc/releases/latest --jq '.tag_name, .published_at'`
- GL core profile support "from 3.2 up to 4.6 inclusive," compatibility-profile features generally unsupported: https://renderdoc.org/docs/behind_scenes/opengl_support.html
- Legacy GL 2.0-and-earlier features are unsupported ("OpenGL is only supported from 3.2 on"): https://renderdoc.org/docs/getting_started/gotchas_known_issues.html
- GL shader debugging exists but requires `ARB_compute_shader` + `ARB_shader_storage_buffer_object` (or core-version equivalent), so "not all GL drivers will be supported," and vertex-shader debugging can be unavailable on many drivers even when supported at all: https://github.com/baldurk/renderdoc/issues/293 , https://renderdoc.org/docs/behind_scenes/opengl_support.html
- KHR_debug object labels and debug groups (`glPushDebugGroup`) are read and displayed by RenderDoc, used to group and colorize draw calls / rename objects in the UI: https://renderdoc.org/docs/how/how_annotate_capture.html
- Python API: separate `renderdoc` module (capture/replay analysis, can be loaded standalone as `renderdoc.pyd` without the UI) and `qrenderdoc` module (UI automation); the standalone `renderdoc` module is the headless path: https://renderdoc.org/docs/python_api/index.html , https://renderdoc.org/docs/python_api/examples/renderdoc_intro.html
- Python module must be loaded with the exact same Python version/build RenderDoc was built against: https://renderdoc.org/docs/python_api/examples/renderdoc_intro.html
- Per-action ("per-draw") GPU timings and tabular GPU counter data are a documented feature, surfaced via the "calculate timings" action and the Performance Counter Viewer: https://renderdoc.org/docs/getting_started/features.html
- MSAA renderbuffers only have a documented display quirk on GLES (appear black in the texture viewer because GLES cannot read unresolved MSAA data); recommended workarounds are to blit to a resolved FBO or use textures instead of renderbuffers — this is a GLES-specific note, not documented as a desktop-GL limitation: https://github.com/baldurk/renderdoc/issues/2972
- Nsight Graphics 2026.3 release notes confirm a legacy "OpenGL Frame Debugger" still exists, but its Shader Profiler is being deprecated in the next release (2026.4), pushing users to GPU Trace instead — GPU Trace itself does not support OpenGL: https://developer.nvidia.com/nsight-graphics/getting-started/release-note-v2026.3
- Nsight Graphics 2026.3 Windows driver requirement is Release 591.86 or newer: https://developer.nvidia.com/nsight-graphics/getting-started/release-note-v2026.3
- Nsight Graphics feature-support matrix: GPU Trace supported for D3D11/D3D12/Vulkan, not for OpenGL; OpenGL users are pointed to the separate Frame Debugger instead: https://forums.developer.nvidia.com/t/nsight-graphics-missing-frame-profiler-activity/257761
- Nsight Graphics is distributed under the NVIDIA Software License Agreement (SLA), free to download after registering for the NVIDIA Developer Program; test/development licenses can carry an expiration (one year from download if unspecified): https://docs.nvidia.com/nsight-graphics/2021.5/CopyrightAndLicenses/index.html , https://developer.nvidia.com/nsight-visual-studio-edition-software-license-agreement-161020
- apitrace is still maintained but only sporadically (maintainer has "very little time"), repository activity as recent as mid-2026: https://github.com/apitrace/apitrace
- GAPID is explicitly no longer under active development; its successor AGI (Android GPU Inspector) is Android-only and still shipping 2025 builds, itself being superseded by Android Performance Analyzer — none of this applies to a Windows/desktop-GL target: https://github.com/google/gapid/blob/master/README.md , https://developer.android.com/agi
- Intel GPA reached end-of-life: 2025.1 was the final release, downloadable through end of 2025, discontinued in 2026, no further fixes or support: https://community.intel.com/t5/Intel-Graphics-Performance/Intel-GPA-End-of-Life-Announcement/m-p/1700732
- PIX is Microsoft's tool for D3D11/D3D12/Xbox only; it has no OpenGL support (general product knowledge, consistent with Microsoft's own PIX documentation scope — no OpenGL capture path exists).

## Implications for the design
- Treat RenderDoc as the only capture/inspect/shader-edit tool in the pipeline; do not budget time to make Nsight Graphics part of the capture workflow.
- Do not rely on RenderDoc's or Nsight's built-in GPU counters as the AO-pass budgeting mechanism. Instrument the renderer directly with `glQueryCounter(GL_TIMESTAMP)` pairs around each pass and surface the deltas in the existing Dear ImGui profiler overlay; use RenderDoc's per-action "calculate timings" view only as a periodic cross-check, not the primary budget source.
- Because the context is created at GL 4.3 (even though shader source is pinned to `#version 410 core` for macOS/4.1 portability), the driver-level features RenderDoc's GL shader debugger needs (`ARB_compute_shader`, `ARB_shader_storage_buffer_object`) should be present on the 12 GB NVIDIA GPU; confirm this once locally before depending on step-through shader debugging for the AO pass.
- For the depth-buffer-at-a-mid-frame-bucket-boundary and MSAA-resolve inspection work, prefer keeping (or temporarily switching) the relevant depth attachment as a texture rather than a renderbuffer when it needs to be sampled/inspected post-resolve; RenderDoc's only documented renderbuffer/MSAA display quirk is GLES-specific, but the target renderer's actual GL desktop behavior should still be spot-checked once before relying on it for depth debugging.
- Nsight Graphics is worth keeping installed only as a secondary, low-effort cross-check for GL state/draw inspection (its legacy Frame Debugger), not for the AO-pass profiling work — its counter/timing engine (GPU Trace) is Vulkan/D3D-only and the GL debugger's own shader profiler is being removed next release.
