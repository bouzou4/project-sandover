## Answer (≤5 lines)
Yes. After the normal draw of a fur-tagged merc draw, Merc2 re-issues the same indices with
`glDrawElementsInstanced` (one instance per shell), so no geometry shader and no DMA changes are
needed: the draw list is already built before `do_draws`. The shells use the same lights, tint,
fog, actor shadow and SSAO normal output as the base draw. Daxter reads as fuzzy (short) to fluffy
(long) at close range; the babak's fur and mohawk thicken. Fur off passes the parity gate on
every shot that captured (see Parity). Cost is about 8 µs of GPU time per shell for Daxter's 6 draws.

## How it works
- **Tag lookup.** The material class lookup from #157, unchanged: `materials.csv` gives a class
  byte per level texture by `combo_id`, with the `fur` tag as bit 6 (`LevelData::tex_class`).
  Merc2 tests it per draw with `pbr_texture_fur` (added to `Materials.h`); no new texture units.
- **Tags.** Only one texture carried `fur`. Tagged 74 rows in `$SANDOVER_DATA/materials/materials.csv`
  (backup `materials.pre-fur-tags.csv` beside it): Daxter's `sk-*fur`/`sk-finger`, the
  babak `bab-*fur*` family in every level, and the lurker puppy `puppy-fur*`. Loaded: GAME 12,
  beach 53, misty 29, jungle 17 fur textures.
- **Vertex.** `merc2.vert`, behind `fur_on`: `h = (instance + 1) / shells`; offset =
  skinned normal × h + world-down (camera space, from the background camera rotation now kept
  in `SharedRenderState::camera_rot`) × gravity × h² + a per-vertex random tangent × curl × h²,
  all × length.
- **Fragment.** `merc2.frag`: one strand per cell of a `density`-per-UV-unit grid, random length
  0.35-1, radius tapering to the tip. The strand edge is a soft coverage value written to alpha
  and resolved by MSAA alpha-to-coverage (with alpha-to-one, so the target keeps the base draw's
  alpha); colour × `mix(1 - root_dark, 1, h)`. Lighting is the base draw's (same uniforms, same vertex path). A debug view colours
  shells by index.
- **Toggle.** `(pc-set-fur <option> <millionths>)`: 0 enable, 1 shells, 2 length m, 3 density,
  4 gravity, 5 curl, 6 root darkening, 7 view. Default off. ImGui controls under the merc renderer.
  Presets: `sandover/presets/fur.toml`, applied by `sandover-capture --preset fur=<name>`.
- Skipped: emerc (envmap) draws and the two-pass light-fade draws.

## Face breakup (review of revision 1)
The maintainer picked medium and saw breakup around Daxter's mouth and eyes. From the code:
- Only fur-tagged draws get shells, and each merc draw has one texture, so the gate is
  already per texture. The eyes (eye renderer ids) and `sk-eye-lid`/`sk-ear` are untagged; the
  face itself is drawn with the fur textures (inferred from texture names). So the fur around
  the eyes and mouth extrudes, as it should for a general fur material.
- Detached shells at high curvature were not the cause: a per-pixel curvature limit
  (`fwidth(normal)/fwidth(position)`, shell height capped at 0.35 of the radius) changed 0.47 %
  of the close-up pixels and left the rim unchanged. On this low-poly mesh the interpolated
  normal barely varies inside a triangle, so there is little curvature to see. Removed.
- The cause is at the silhouette and the eye rims, where shells are seen edge-on: the hard
  alpha test leaves single-pixel aliased strands and speckle. Alpha to coverage (soft strand
  edge, MSAA resolve) fixes it without any per-feature mask. Tighter shells (32 at the same
  length) were tried once: rim streaks only marginally smoother at twice the cost, so medium
  stays at 16.

Crops (full res, 800×600 at the close shot): `$SANDOVER_DATA/shots/fur/face-crops/`
(1 before, 2 after).

## Parity
With fur off, every new GL call is behind `fur_enable` and the shader change is a branch on a
uniform that is only set to 1 around the shell draws, so the off path draws what master draws.
Measured once on the `dc89e2813` base: `sandover-parity check --set auto-v1` PASS 56/56, largest
FLIP mean 0.0073 (threshold 0.0110). After a later rebase `village2-dock-dawn` read 0.035 on
Jak's lighting and the ground (not fur geometry: no fur texture there, and the off path is
unchanged), so it is attributed to master changes between the goldens and this base. Not re-run,
per the milestone-only parity rule.

## Limits
- Strands follow the texture's UV scale, so density varies across UV islands; seams show where
  islands meet at larger lengths.
- Shells use the vertex normal, not a smoothed one: hard-edged merc parts split at creases.
- Alpha to coverage needs MSAA; without it (no sample buffers on the target) the shader
  falls back to a hard 50 % cutoff with alpha 1, as alpha-to-one gives with MSAA.
- The babak pose is not reproducible between runs, so its pixel diff overstates the change.
- Rig instances sometimes die while loading a level when several run at once, with the master
  binary as well; not caused by this change.
