## Answer (<=5 lines)
Gradio is Apache-2.0 (whole monorepo, Python and Svelte frontend, single LICENSE file), actively maintained, and runs fully on Windows via pip/uv. It defaults to phoning home (analytics ping + PyPI version check on launch) and to downloading an frpc binary if `share=True`; both must be explicitly disabled for an airtight offline setup. `gr.Gallery.select()` gives a real index via `evt.index`, supports click-to-enlarge preview, but has no documented keyboard-nav guarantee and no built-in side-by-side/slider comparison outside the separate `gr.ImageSlider` (2-image-only, not 5-way). For a bare 1-of-5 click-and-write flow, a static HTML contact sheet + stdlib `http.server` is simpler and has zero telemetry surface — but Gradio's built-ins (gallery, state, TOML write-back via Python) still net less code for this exact use case.

## Evidence
- License is Apache-2.0 for the whole repo (Python server + `js/` Svelte frontend live in one monorepo under the root LICENSE): https://github.com/gradio-app/gradio/blob/main/LICENSE
- Repo metadata via `gh api`: SPDX `Apache-2.0`, pushed 2026-09-23T02:39:59Z, 43,606 stars, 98 open issues (queried 2026-09-23).
- Latest release tag `gradio@6.28.0`, published 2026-09-18T11:55:43Z (queried via `gh api repos/gradio-app/gradio/releases/latest`, 2026-09-23).
- `GRADIO_ANALYTICS_ENABLED` env var (default `"True"`) controls telemetry; can also pass `analytics_enabled=False` to `launch()`: https://discuss.huggingface.co/t/analytics-enabled-error-where-are-the-variables-set-on-what-to-collect-or-telemetry-data-gets-sent/25648
- Gradio posts `initiated_analytics`/`launched_analytics` events and does a `utils.version_check()` HTTP GET against PyPI on every app instantiation by default, which can hang for minutes with no network and is only ~loosely tied to the analytics flag: https://github.com/gradio-app/gradio/issues/2726 and https://github.com/gradio-app/gradio/issues/8671
- `share=True` downloads and runs an `frpc` binary to tunnel through Gradio's hosted FRP share server; frpc is commonly flagged by antivirus as a hacktool/riskware and has had an insecure-transport CVE — keep `share=False` (the default) for a local-only deployment: https://github.com/gradio-app/gradio/issues/11928 and https://huggingface.co/blog/gradio-5-security
- `GRADIO_SHARE` env var (default `"False"`) is an alternate way to force sharing off; `GRADIO_SERVER_NAME` defaults to `127.0.0.1` (loopback-only) unless overridden to `0.0.0.0`: https://gradio.app/guides/environment-variables
- Frontend does load Google Fonts from a CDN by default; a documented offline patch swaps in local font CSS to avoid any outbound font request: https://gist.github.com/XFY9326/8c6c89950a8eeed32d4990f01ee0c587
- `gr.Gallery.select()` fires a `gradio.SelectData` object whose `.index` attribute gives the clicked item's index (int for a flat gallery); worked example: `def get_select_index(evt: gr.SelectData): return evt.index`: https://gradio.app/docs/gradio/selectdata
- Gallery supports click-to-enlarge preview (`allow_preview`, default True) and can open directly in preview mode via `preview=True` / `selected_index`; current docs do not call out keyboard-navigation behavior explicitly: https://gradio.app/docs/gradio/gallery
- There is no native N-way gallery comparison slider; the closest built-in is `gr.ImageSlider`, a two-image before/after clip-path slider component, not a 5-image selector: https://github.com/gradio-app/gradio/issues/9708 and https://www.gradio.app/main/docs/gradio/imageslider
- Gallery/Image postprocessing re-encodes numpy/PIL inputs through the `format` parameter (defaults toward PNG); PNG re-encodes of large images run ~10x larger than JPEG equivalents, so format should be set explicitly for performance: search result summarizing gradio-app/gradio issue #7486 discussion, https://github.com/gradio-app/gradio/issues/7486
- Base64-embedded gallery images previously caused serious input lag (Safari-specific issue), fixed by switching Gallery/Image postprocess to serve tempfiles instead of base64: https://github.com/gradio-app/gradio/issues/1590
- File serving is allowlist-based: `allowed_paths`/`GRADIO_ALLOWED_PATHS`, `blocked_paths`, the app's cache dir, and cwd are the only servable locations; `GRADIO_TEMP_DIR` overrides the temp/cache directory: https://gradio.app/guides/file-access and https://gradio.app/guides/environment-variables
- Windows-specific `allowed_paths` friction reported: subdirectories under an allowed parent path can still raise `InvalidPathError` in some versions, and one workaround thread shows users adding every drive letter to `allowed_paths` on Windows: https://github.com/gradio-app/gradio/issues/9766
- Chrome on Windows blocks locally-compiled Svelte custom-component files for security reasons; Gradio's own team currently recommends developing custom components under WSL rather than native Windows because of this: search result citing gradio-app guidance (query "Gradio Windows support issues 2026 uv install", 2026-09-23) — this only affects building new custom components, not running stock `gr.Gallery`/`gr.ImageSlider`.
- Streamlit: Apache-2.0. NiceGUI: MIT. Panel (holoviz/panel): BSD-3-Clause. marimo: Apache-2.0. https://github.com/streamlit/streamlit, MIT license per bitdoze.com/hysenlabs comparison writeups, https://github.com/holoviz/panel, https://github.com/marimo-team/marimo/blob/main/LICENSE

## Implications for the design
- Treat Gradio as "buy": it covers gallery display, click selection with index, and state management in a few dozen lines, saving real build time over a custom picker.
- For the offline/private requirement, the launch script must set, before `import gradio`: `GRADIO_ANALYTICS_ENABLED=False` (belt-and-suspenders with `analytics_enabled=False` on `.launch()`), never pass `share=True` (leave default `False` / `GRADIO_SHARE=False`), keep `server_name="127.0.0.1"` (default), and set `GRADIO_TEMP_DIR` to a project-local scratch folder so cached gallery images don't accumulate in the system temp dir. The version-check-on-launch HTTP call is a real outbound request even with analytics off in some versions — if a fully air-gapped machine is required, confirm at integration time that disabling analytics also suppresses the PyPI version check, or block outbound HTTP at the OS firewall level for this process as a backstop.
- Google Fonts CDN loading is a genuine offline/privacy gap for a page that must never touch the network; apply a local-font patch or bundle a local stylesheet override before shipping.
- Pass `format="jpeg"` (or pre-encode candidates to JPEG before handing them to the gallery) for the 5x 2560x1440 round to avoid PNG re-encode bloat; current Gradio versions already serve gallery images as tempfiles rather than base64, so per-request payload size is the main remaining lever.
- `gr.ImageSlider` does not fit a 5-candidate flow (it's strictly 2-image before/after); if a compare view is wanted later, it would need to be built as a custom pairwise comparison, not repurposed wholesale.
- Set `allowed_paths` to the exact candidate-image output directory (not a drive root) and verify subdirectory serving works on the target Gradio version before relying on it — Windows users have hit `InvalidPathError` on nested allowed paths.
- A static HTML contact sheet (five `<img>` tags, one JS click handler, a tiny stdlib `http.server`-based POST receiver to write the TOML) is simpler and has strictly zero telemetry/CDN/tunnel surface to audit. Given the offline/privacy bar here, this is a credible alternative to Gradio for this one narrow screen, at the cost of writing the click-and-write plumbing by hand instead of getting it from the library.
