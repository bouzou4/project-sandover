## Answer (<=5 lines)
BoTorch's `PairwiseGP` + `AnalyticExpectedUtilityOfBestOption` (EUBO/qEUBO) is a maintained, MIT-licensed, CPU-capable path for a 3-8 dim, tens-of-rounds preference loop; a 1-of-5 pick is encoded as 4 pairwise comparisons (winner beats each loser) and `q`-batch EUBO gives multiple candidates per round, though "diversity" among them is not explicitly optimized. Sequential Gallery is design-reference only: MIT but C++/Qt5 with a `pysps` pybind11 wrapper, no standalone reusable Python BO code, and its README does not contain enough algorithmic detail to reimplement plane search without reading the paper. For round 1, "keep the winner, jitter" is good enough and defers BO until enough preference data exists to fit a GP; BO is worth adding once a session accumulates ~10-15+ rounds or persists across sessions.

- `botorch/models/pairwise_gp.py` exists in the current tree and was last modified 2026-04-20 (commit 75fe56b), i.e. actively maintained this year: `gh api "search/code?q=repo:meta-pytorch/botorch+filename:pairwise_gp.py"` and `gh api "repos/meta-pytorch/botorch/commits?path=botorch/models/pairwise_gp.py"`.
- "Bayesian optimization with pairwise comparison data" tutorial confirms `PairwiseGP` is fit via `PairwiseLaplaceMarginalLogLikelihood`, comparisons are generated from "all possible pairs of elements," `AnalyticExpectedUtilityOfBestOption` (EUBO) is the acquisition function, the loop runs 30 rounds after an initial random batch, initial data is randomly sampled from the unit cube, and the tutorial explicitly demonstrates batch queries (`q=2` points, `q_comp=1` comparisons per query): https://botorch.org/docs/tutorials/preference_bo/.
- qEUBO acquisition function ("qEUBO: A Decision-Theoretic Acquisition Function for Preferential Bayesian Optimization," Astudillo, Lin, Bakshy, Frazier, AISTATS 2023) is one-step Bayes-optimal under noise-free responses and has an additive-constant guarantee under noisy responses, with simple regret converging at o(1/n): https://arxiv.org/abs/2303.15746, https://proceedings.mlr.press/v206/astudillo23a.html.
- Ax has added `PairwiseGP` support in ModelList pipelines and "dispatch of qEUBO for preferential Bayesian optimization" per its changelog, version 1.3.1 released 2026-06-09, repo pushed 2026-09-21, MIT, 2807 stars, 185 open issues: https://github.com/facebook/Ax/blob/main/CHANGELOG.md, `gh api repos/facebook/Ax`.
- Sequential Gallery repo: MIT license, last push 2025-11-11, 22 stars, 0 open issues, C++ with Qt5 and Eigen, `pysps` pybind11 Python bindings installable via `pip install git+https://github.com/yuki-koyama/sequential-gallery`, README defers the plane-search/line-search algorithm description to the SIGGRAPH 2020 paper rather than documenting it inline: https://github.com/yuki-koyama/sequential-gallery, `gh api repos/yuki-koyama/sequential-gallery`.
- Sequential Gallery paper (Koyama & Sato, SIGGRAPH 2020, arXiv 2005.04107) proposes "sequential plane search," decomposing an n-dimensional preference search into a sequence of 2D subspace searches shown as a gallery grid, reported to outperform the earlier "sequential line search" 1D approach: https://arxiv.org/abs/2005.04107.
- `sequential-line-search` and `mathtoolbox` (git submodules of Sequential Gallery) are both MIT-licensed and were also last touched 2025-11-11 (same batch update), version tag v0.5: `gh api repos/yuki-koyama/sequential-line-search`, `gh api repos/yuki-koyama/mathtoolbox`.
- No maintained PyPI package named "preferential" or a clear "pybo" successor was found; `GPro` exists on PyPI as a small preference-GP package but was not further vetted: web search results for `"preferential" python package pairwise preference Bayesian optimization pypi`.

## Implications for the design
- Encode each round's 1-of-5 pick as 4 pairwise comparisons (winner vs. each loser) and feed them to `PairwiseGP` — this matches exactly how the official BoTorch tutorial constructs its training data, so no custom likelihood work is needed.
- BoTorch runs CPU-only on the target workstation without any CUDA dependency; the GPU is irrelevant to this component (rendering candidates is the GPU-bound step, not GP fitting).
- Use EUBO/qEUBO with `q=5` to propose the next batch of candidates, but note the tutorial's batch mode optimizes joint expected utility of the best option in the batch, not an explicit diversity term — if the 5 proposals cluster too tightly in practice, a cheap fix is to add a post-hoc diversity filter (e.g. greedy max-min distance in parameter space) on top of the acquisition function's output rather than relying on BoTorch alone.
- Do not depend on the Sequential Gallery repo directly (C++/Qt5/pybind11 build chain is unnecessary weight for a uv-managed Python project); treat the paper's plane-search idea as something to reimplement thinly if/when a 2D-subspace-at-a-time interaction is wanted, layered on top of BoTorch's GP rather than replacing it.
- Given the budget is "tens of rounds" for 3-8 dimensions, start with 1-2 rounds of Sobol/random candidates (matches the tutorial's random initialization) before switching to EUBO-driven proposals, and treat round-1 as the dumb "keep the winner, jitter" baseline until there is enough comparison data (roughly after the first 2-3 rounds) to fit a stable `PairwiseGP`.
- Skip Ax for now — it adds a service-API and versioning layer around the same PairwiseGP/qEUBO machinery, and its preference-learning support (ModelList + qEUBO dispatch) is recent enough in the changelog that going straight to BoTorch's own tutorial code is the lower-risk path.
