## Answer (<=5 lines)
trimesh's GLTF loader only reads/writes `COLOR_0`; `COLOR_1..COLOR_7` are never referenced in its loader code and are silently dropped, so it cannot round-trip 8 colour sets on its own. pygltflib is a thin dataclass wrapper around the raw glTF JSON/accessor/GLB-chunk structure and does not special-case colour attribute names, so arbitrary `COLOR_n` accessors pass through untouched on read and write. Recommended split: pygltflib for all accessor-level I/O (positions, normals, UVs, all 8 colour sets, GLB binary chunks), trimesh only as an optional numpy-array helper for geometric-normal computation, fed pre-extracted position/face arrays with `process=False` and no `merge_vertices()` call.

- gltflib (sergkr/gltflib, mirrored at pygfx/gltflib): MIT license, 183 stars, 10 open issues, last PyPI release 1.0.13 uploaded 2022-08-22: `gh api repos/pygfx/gltflib` and PyPI JSON API (`https://pypi.org/pypi/gltflib/json`)

## Implications for the design
- Use pygltflib as the sole read/write path for the decompiler's `.glb` exports: it must own extraction of `COLOR_0..COLOR_7` accessors (verifying `componentType`/`normalized` per set), positions, normals, and UVs, and the write-back of per-vertex fit-residual colours as new/overwritten `COLOR_n` accessors.
- Do not route colour data through trimesh at any point — even with `process=False`, trimesh's GLTF loader never surfaces `COLOR_1..COLOR_7`, so those sets would need to be reattached to trimesh's array after the fact, which is more code than just keeping trimesh out of the colour path entirely.
- If geometric-normal computation is needed for meshes missing `NORMAL`, extract `POSITION`/faces via pygltflib into numpy arrays, construct a `trimesh.Trimesh(vertices=..., faces=..., process=False)` purely for that computation, read back `.vertex_normals`, and never call `merge_vertices()` on that object — this keeps vertex order (and therefore the colour-accessor row alignment) intact.
- Minimal dependency footprint for this tool: `pygltflib` (pure Python) plus `trimesh` with no extras (bare `numpy` dependency is enough for normals; skip `shapely`/`rtree`, which are for 2D vector-path formats the tool does not use). Both install cleanly on Windows via `uv` with no compiled-extension pain expected.
