# Level heightfield (Jak 1)

Shared infrastructure: a top-down map of the solid world per level, for sun occlusion (foliage
backlight, terrain and buildings shading actors) and water (floods passing under piers).
Code: `game/graphics/opengl_renderer/LevelHeightfield.{h,cpp}`, `shaders/level_height.glsl`.

## What it holds

Built at level load (loader thread) from the level's collision mesh (`tfrag3::CollisionMesh`,
the `collision` member of the fr3 level), two layers per texel:

| Layer | Meaning | No collision |
|---|---|---|
| top | highest collision surface: roofs, cliffs, overhangs, so anything under them reads as blocked from the sun | -inf (GPU r = 0) |
| bottom | lowest collision surface: floors under piers, stilts, bridges and arches, so water can pass under | +inf (GPU g = 65535) |

Rasterised from every collision triangle: texel centres inside its xz footprint, plus samples
along its edges every half texel (walls have no footprint; their top edges count).

- Resolution: 1 m texels; the texel grows in whole metres so no side exceeds 2048 texels. The
  extent is the 0.2-99.8% range of the collision vertices plus 50 m, so a few stray far vertices
  do not coarsen the map.
- Memory: 8 bytes per texel on the CPU (two floats), 4 bytes plus mips on the GPU (RG16).
  Expected 1-15 MB CPU per level (jungle about 350 x 365 m, ogre about 1 x 1.7 km); the load log
  prints the real size and build time (`heightfield: <level> WxH texels of T m, X MB, Y ms`).
- Which levels: only levels whose level-info has `:sky #t` (`LevelSky.inc`, generated by
  `sandover-levelinfo --write-inc`; a test checks it matches level-info.gc). Caves and interiors
  (maincave, darkcave, robocave, lavatube, citadel, jungleb, sunken, ...) get none, cost nothing,
  and every consumer reads them as open.
- Level borders and vista neighbours: each loaded level has its own map. Per frame,
  `heightfield_prepare` uploads the maps of the two loaded levels nearest the camera into a
  two-layer array (unit 32, sampler `lh_tex` set explicitly) with stable slots: the map the camera
  is over first, then the nearest by centre; a slot is re-uploaded only when its map changes, and
  only while a consumer is enabled (`heightfield_wanted()`). A point outside both reads as open (a
  third, vista-only level's geometry is not tested). The RG16 mip chain (max of top, min of
  bottom, 7 levels, halving rounded up so texel i sits in cell i >> k and an odd last row or
  column is kept) is built on the loader thread; heights encode to 1..65534, 0 = no top, 65535 =
  no bottom. Layers are allocated at a multiple of 64 texels a side, so every GL level holds whole
  cells; the shader takes the texel index from world xz and shifts it by the lod, and reads with
  texelFetch (nearest), so markers and max/min cells are never blended.
- The CPU map is built for every sky level at load whatever `heightfield_wanted()` says: CPU
  readers (`height_top`, the terrain sun) need it with no GPU consumer. Only the GPU upload waits
  for a consumer. A slot change uploads every mip of that layer on the render thread (up to about
  16 MB for the top level of a 2048 x 2048 map), which can hitch on a level change; the array is freed when no map
  is wanted.

## API

C++ (render thread unless noted):

- `heightfield_build(mesh, level, spec)`: build (thread-safe); `HeightfieldSpec` holds the texel,
  a height range and an optional xz region.
- `LevelHeightfield::height_top(x, z)`, `height_bottom(x, z)`: metres, per texel (no filtering).
- `heightfield_of(LevelData*)`: the level's map or null. `LevelData::heightfield` holds it.
- `heightfield_prepare(render_state)`: per frame, after `prime_camera_jak1`.
- `heightfield_set_uniforms(program)`: binds unit 32 and the `lh_*` uniforms (cached lookups) for
  a program that includes the GLSL helper; leaves the active unit as found (with the
  PERF_OPT_GEOMETRY + 2 bit on it assumes GL_TEXTURE0 is active, the convention between passes).
- `heightfield_wanted()`: consumers add their switch there.
- `heightfield_level_has_sky(level)`.

GLSL (`LEVEL_HEIGHT_GLSL` token, include guard so a shader may pull it in twice; game units):

- `lh_top(xz, lod)`, `lh_bottom(xz, lod)`: nearest texel over a footprint of 2^lod texels; the
  mips hold the max of top and the min of bottom, so a coarse lookup never misses a roof or a gap.
- `lh_sun_blocked(p, L, start_m, margin_m)`: share of the sun blocked at p along L (toward
  the sun): ten taps out to about 70 m past `start_m`, each footprint growing with distance,
  soft over +-margin_m; the lod is picked per slot from that map's own texel. Start a few metres
  out to skip the receiver's own pole or trunk.

Debug: Renderer Debug -> Level heightfield: the maps in use and a preview (top as grey, texels
whose bottom lies well below their top tinted blue: under a roof or bridge).

## Slab variant (planned, not built)

For places that cannot be mapped as a whole (caves, stacked passages): the same builder with a
`HeightfieldSpec` whose `y_min`/`y_max` bound the surfaces that count and whose region limits
the extent, e.g. per water body the floor between the water height and the first surface above
it. Only the spec changes; the rasteriser already filters samples by height and region. A slab
would be stored per region (a list next to `LevelData::heightfield`) and bound the same way.

## Known limits

Top-down: an overhang shades everything under it at any sun height (conservative: less light,
never more); thin features below about a texel are kept by the edge samples but blur in the mips.
